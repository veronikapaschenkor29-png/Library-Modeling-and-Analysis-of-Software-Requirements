# 0007. Послідовність на сценарій (одна діаграма на use case)

- **Status:** прийнято
- **Date:** 2026-11-17

## Контекст та постановка проблеми

Для кожного use case потрібна sequence-діаграма. Потрібно вирішити, як організувати діаграми: одна на use case, чи одна загальна з усіма сценаріями.

## Розглянуті варіанти

1. **Одна загальна sequence-діаграма** з усіма сценаріями (S1-S5).
   - Переваги: повна картина взаємодії.
   - Недоліки: складна для читання, багато перетинів.

2. **Окрема sequence-діаграма на кожен сценарій** (S1 - видача, S2 - повернення, S3 - бронювання, S4 - пошук, S5 - сповіщення).
   - Переваги: читабельність, ізоляція сценаріїв.
   - Недоліки: дублювання спільних частин (автентифікація).

## Рішення

Обрано **Варіант 2** - окрема sequence-діаграма на кожен сценарій.

### Позитивні наслідки

- **Читабельність:** Кожна діаграма фокусується на одному сценарії.
- **Тестування:** Легко простежити логіку кожного сценарію.
- **Без activation bars:** Діаграми спрощені для кращої читабельності.

### Негативні наслідки

- Дублювання спільних частин (автентифікація, перевірка боргів).

## Пов'язані рішення

- ADR 0005: Перевірка боргів при видачі (S1 включає перевірку боргів).
- ADR 0006: Штраф як extend на повернення (S2 включає нарахування штрафу).
