## Розглянуті варіанти

1. **Послідовні перевірки** (if-else каскад).
   - Переваги: простота.
   - Недоліки: не відображає паралельність, довга діаграма.

2. **Fork/Join** — паралельні гілки перевірок.
   - Переваги: відображає паралельність, компактність.
   - Недоліки: складніше для читання.

## Рішення

Обрано **Варіант 1** — послідовні перевірки (if-else каскад) для спрощення діаграми.

### Позитивні наслідки

- **Читабельність:** Діаграма проста для розуміння.
- **Спрощення:** Менше перетинів, зрозумілий потік.
- **3 смуги:** Читач/Система/Бібліотекар — чітке розділення відповідальності.

### Негативні наслідки

- Не відображає паралельність перевірок (але це прийнятно для бізнес-логіки).

## Пов'язані рішення

- ADR 0005: Перевірка боргів при видачі.
- ADR 0009: Модульний моноліт (перевірки виконуються послідовно в одному модулі).
