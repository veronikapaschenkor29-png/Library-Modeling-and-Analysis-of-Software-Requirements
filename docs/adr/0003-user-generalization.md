# 3. USER з узагальненням MEMBER / LIBRARIAN

* Статус: прийнято
* Дата: 2026-11-23

## Контекст та постановка проблеми
Один обліковий запис може мати різні ролі (читач, бібліотекар). Потрібно розділити автентифікацію та профілі ролей.

## Розглянуті варіанти
* **Варіант 1:** Зберігати атрибути ролей прямо в `USER` (поля `status`, `employee_code`).
* **Варіант 2:** Виділити `MEMBER` і `LIBRARIAN` як окремі сутності з FK до `USER` (узагальнення).

## Рішення
Обрано **Варіант 2** — узагальнення через `MEMBER` і `LIBRARIAN`.

### Позитивні наслідки
* `USER` містить лише дані автентифікації, без зайвих NULL-полів.
* Легко додавати нові ролі без зміни `USER`.
* Читач і бібліотекар можуть бути різними записами, пов'язаними з одним користувачем.

### Негативні наслідки
* Додатковий `JOIN` при вибірці профілю користувача.
