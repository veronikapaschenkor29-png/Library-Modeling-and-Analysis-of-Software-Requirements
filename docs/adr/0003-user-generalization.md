# 0003. Узагальнення USER → MEMBER / LIBRARIAN

- **Status:** прийнято
- **Date:** 2026-11-17

## Context
Система має дві ролі користувачів (читач і бібліотекар) з різними атрибутами профілю, але спільною автентифікацією (email, пароль, ім'я).

## Decision Drivers
- Спільна автентифікація для всіх ролей.
- Різні профільні атрибути для кожної ролі.
- Можливість додати нову роль без зміни таблиці автентифікації.

## Considered Options
1. **Одна таблиця `USER` з усіма атрибутами всіх ролей (nullable).**
   - Плюси: одна таблиця, прості запити.
   - Мінуси: багато NULL-полів, порушення 3NF, складно додати роль.
2. **Окремі таблиці `MEMBER` і `LIBRARIAN` без спільного `USER`.**
   - Плюси: кожна роль має свої атрибути.
   - Мінуси: дублювання email/пароля/імені, складна автентифікація.
3. **Узагальнення: `USER` (автентифікація) + `MEMBER`/`LIBRARIAN` (профілі, 1:0..1).**
   - Плюси: спільна автентифікація, профілі розділені, легко додати роль.
   - Мінуси: JOIN при отриманні профілю.

## Decision
Обрано **Варіант 3** - узагальнення `USER` → `MEMBER`/`LIBRARIAN`.

## Consequences
- Позитивні: автентифікація спільна, профілі розділені, модель розширювана.
- Негативні: JOIN при отриманні профілю користувача.
