# 0001. Виділення сутності BOOK_COPY для обліку примірників

- **Status:** прийнято
- **Date:** 2026-11-16

## Контекст та постановка проблеми

У бібліотеці необхідно розмежувати бібліографічний опис книги (BOOK) та фізичні примірники (BOOK_COPY), які мають інвентарний номер, стан та статус. Потрібно вирішити, як моделювати володіння примірниками та їх видачу.

## Розглянуті варіанти

1. **Додавання атрибутів примірника безпосередньо в таблицю BOOK** (інвентарний номер, стан, статус).
   - Переваги: простіша схема, менше JOIN.
   - Недоліки: порушення 3NF, дублювання бібліографічних даних (назва, автор, ISBN) для кожного примірника, складно оновлювати.

2. **Виділення окремої сутності BOOK_COPY**, пов'язаної з BOOK відношенням 1 : 0..N.
   - Переваги: 3NF, чистота схеми, окремий облік кожного примірника (інвентарний номер, стан, статус), можливість відстежувати історію позик.
   - Недоліки: додатковий JOIN при запитах.

## Рішення

Обрано **Варіант 2** — виділення сутності BOOK_COPY.

### Позитивні наслідки

- **3NF:** Атрибути примірника (inventory_number, status, condition) ізольовані в окремій таблиці, бібліографічні дані не дублюються.
- **Облік примірників:** Кожен примірник має унікальний інвентарний номер та статус (доступний/на руках/заброньований/списаний).
- **Історія позик:** LOAN прив'язаний до конкретного примірника (book_copy_id), що дозволяє відстежувати, хто і коли брав конкретний примірник.
- **Гнучкість:** Можна додавати нові примірники без зміни бібліографічного опису.

### Негативні наслідки

- Додатковий JOIN при запитах наявності книги (BOOK → BOOK_COPY).
- Потребує додаткового індексу на book_copy.book_id для продуктивності.

## Пов'язані рішення

- ADR 0004: Штраф за прострочення (FINE прив'язаний до LOAN, який прив'язаний до BOOK_COPY).
- ADR 0007: Послідовність на сценарій (видача книги працює з BOOK_COPY).
