# 0002. Асоціативна сутність BOOK_AUTHOR для зв'язку книга-автор

- **Status:** прийнято
- **Date:** 2026-11-16

## Контекст та постановка проблеми

Книга може мати кількох авторів, а автор — кілька книг. Потрібно зберігати порядок авторів (перший автор, співавтори) та забезпечити цілісність зв'язку.

## Розглянуті варіанти

1. **Додавання масиву author_ids у таблицю BOOK** (PostgreSQL array).
   - Переваги: простий запит.
   - Недоліки: порушення 1NF, складно індексувати, неможливо зберегти порядок авторів без додаткової логіки.

2. **Асоціативна сутність BOOK_AUTHOR** з полями book_id, author_id, author_order.
   - Переваги: 3NF, збереження порядку авторів (author_order), можливість додавати метадані (роль автора: автор, редактор, перекладач).
   - Недоліки: додатковий JOIN.

## Рішення

Обрано **Варіант 2** — асоціативна сутність BOOK_AUTHOR.

### Позитивні наслідки

- **3NF:** Зв'язок M:N нормалізований через проміжну таблицю.
- **Порядок авторів:** Поле author_order зберігає послідовність (1 — перший автор, 2 — другий тощо).
- **Розширюваність:** Можна додати поле role (автор, редактор, ілюстратор) без зміни схеми.
- **Цілісність:** FK на BOOK та AUTHOR забезпечують referential integrity.

### Негативні наслідки

- Додатковий JOIN при запитах на список авторів книги.
- Потребує індексу на (book_id, author_order) для сортування.

## Пов'язані рішення

- ADR 0001: Виділення BOOK_COPY (BOOK — центральна сутність, навколо якої будується модель).
- ADR 0003: Узагальнення USER (автори — окрема сутність, не пов'язана з USER).
