# 0002. Асоціативна сутність BOOK_AUTHOR з author_order

- **Status:** прийнято
- **Date:** 2026-11-17

## Context
Книга може мати кількох авторів, і порядок авторів має значення (перший автор — основний). Зв'язок «книга ↔ автор» — M:N.

## Decision Drivers
- Збереження порядку авторів.
- Уникнення дублювання авторів у таблиці книг.
- Нормалізація (3NF).

## Considered Options
1. **Зберігати авторів у полі `BOOK.authors` (рядок/JSON).**
   - Плюси: простіше зберігати.
   - Мінуси: неатомарне значення, неможливо нормально індексувати/шукати, порушення 1NF.
2. **Пряме M:N через сполучну таблицю `book_author` без атрибутів.**
   - Плюси: нормалізована M:N.
   - Мінуси: порядок авторів втрачається (або вимагає окремого поля, що по суті робить його асоціативною сутністю).
3. **Асоціативна сутність `BOOK_AUTHOR(book_id, author_id, author_order)`.**
   - Плюси: зберігає порядок, нормалізована, розширювана (можна додати роль автора).
   - Мінуси: додаткова таблиця і JOIN.

## Decision
Обрано **Варіант 3** — асоціативна сутність `BOOK_AUTHOR` з `author_order`.

## Consequences
- Позитивні: порядок авторів збережено; автори не дублюються; модель розширювана.
- Негативні: додатковий JOIN при виведенні списку авторів книги.
