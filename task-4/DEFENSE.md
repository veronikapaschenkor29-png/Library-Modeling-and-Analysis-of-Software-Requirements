# DEFENSE - Завдання 4: Діаграма діяльності бібліотеки

## §1. Намір і критерії

Намір: описати UC_Borrow (видача книги) як єдиний бізнес-процес з усіма сценаріями Gherkin S1-S5 на одній діаграмі діяльності зі смугами, паралельними перевірками, повідомленнями і трасуванням «сценарій → шлях» (spec.md §1-§4, §8).

Що доведено:
- Єдиний бізнес-процес видачі з усіма сценаріями Gherkin (S1-S5) на одній діаграмі діяльності.
- Форма: PlantUML activity зі смугами (Читач, Система, Бібліотекар).
- Розгалуження з вичерпними умовами (борги, ліміт 5, наявність примірника, блокування).
- Паралельна гілка для перевірок боргів (LOAN) і примірника (BOOK_COPY).
- Повідомлення читачеві з показаною реакцією («Пропонується бронювання», «Відмова: є прострочені борги», «Відмова: перевищено ліміт 5 книг», «Примірник недоступний (блокування)»).
- Трасування «сценарій → шлях» для S1-S5 (spec.md §8).

Критерії прийняття (spec.md §10):
- Одна форма (діаграма діяльності), декларативний опис.
- ≥1 розгалуження з вичерпними умовами.
- ≥1 паралельна гілка.
- ≥1 повідомлення з показаною реакцією.
- Кожен сценарій Gherkin = шлях.
- Смуги ⊆ учасники послідовності.
- Вузли даних ⊆ сутності ER (MEMBER, LIBRARIAN, BOOK_COPY, LOAN, RESERVATION).

## §2. Топ-3 розбіжності, виправлені в цій лабі

1. Сценарії по окремих діаграмах → єдиний процес.
   Було: у діаграмах послідовності (Завдання 3) кожен сценарій S1-S5 мав окрему діаграму з власним блоком alt. Стало: усі сценарії об'єднано в один процес діяльності зі спільними розгалуженнями і єдиним початком/кінцем.

2. Послідовні перевірки → паралельні.
   Було: перевірки боргів (LOAN) і примірника (BOOK_COPY) виконувалися послідовно. Стало: обидві перевірки запускаються одночасно, а синхронізація гарантує завершення обох перед розгалуженням.

3. Лише внутрішні виклики → повідомлення з очікуванням відповіді.
   Було: система лише викликала сервіси без показу реакції читача. Стало: додано повідомлення «Пропонується бронювання» з очікуванням підтвердження або відмови читача, а також повідомлення про блокування примірника.

## §3. Ключове рішення

Обрано діаграму діяльності з трьома смугами (Читач, Система, Бібліотекар), бо процес має розгалуження і паралельні перевірки, а запитання «що треба зробити і хто» відповідає діаграмі діяльності (методика 9.10).

Альтернативи:
- Машина станів: об'єкт LOAN не має станів переходів у межах процесу.
- BPMN: процес всередині системи, а не між пулами організацій.

## §4. Перевірка

| Сценарій (S1-S5) | Шлях на діаграмі | Розгалуження/повідомлення | Перевірка |
| :--- | :--- | :--- | :--- |
| S1 Успішна видача | Початок → перевірка боргів (немає) → перевірка ліміту (<5) → примірник доступний → створити LOAN → встановити статус «на руках» → кінець | борги (ні), ліміт (ні), примірник (так); паралельна гілка | огляд |
| S2 Книги немає → бронювання | Початок → перевірка боргів (немає) → перевірка ліміту (<5) → примірник недоступний → створити RESERVATION → кінець | примірник (ні); «Пропонується бронювання» з очікуванням відповіді | огляд |
| S3 Борги → відмова | Початок → перевірка боргів (є прострочені) → відмовити → кінець | борги (так); «Відмова: є прострочені борги» | огляд |
| S4 Ліміт → відмова | Початок → перевірка боргів (немає) → перевірка ліміту (≥5) → відмовити → кінець | ліміт (так); «Відмова: перевищено ліміт 5 книг» | огляд |
| S5 Блокування примірника | Початок → перевірка боргів (немає) → перевірка ліміту (<5) → примірник недоступний (статус «на руках») → відмовити (блокування) → кінець | примірник (ні, статус «на руках»); «Примірник недоступний (блокування)» | огляд |
| Паралельна гілка | не застосовно | обидві перевірки завершуються перед розгалуженням | огляд |
| Умови вичерпні | не застосовно | кожне if має гілки так/ні і завершення | огляд |
| Смуги ⊆ учасники послідовності | не застосовно | Читач, Система, Бібліотекар ⊆ учасники Завдання 3 | огляд |
| Вузли даних ⊆ сутності ER | не застосовно | MEMBER, LIBRARIAN, BOOK_COPY, LOAN, RESERVATION | огляд |

Заборонено: символ «—» (лише «-»), STORE, PRODUCT, ORDER, REVIEW, CATEGORY, Seller, Customer, Anonymous, BOOK_GENRE.
