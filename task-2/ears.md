# EARS-вимоги: бібліотека

## Функціональні вимоги (EARS-01..EARS-11)

| ID | Тип | Вимога | UC |
| :--- | :--- | :--- | :--- |
| EARS-01 | Подієва | КОЛИ `Reader` запитує видачу І примірник доступний, ТО система ПОВИННА створити `LOAN` з терміном 14 днів. | UC_Borrow |
| EARS-02 | Небажана ситуація | ЯКЩО `Reader` має прострочені борги, ТО система ПОВИННА відмовити у видачі з повідомленням. | UC_Borrow |
| EARS-03 | Небажана ситуація | ЯКЩО `Reader` уже має 5 активних позик, ТО система ПОВИННА відмовити у видачі. | UC_Borrow |
| EARS-04 | Подієва | КОЛИ примірника немає в наявності, ТО система ПОВИННА запропонувати бронювання і створити `RESERVATION`. | UC_Borrow, UC_Reserve |
| EARS-05 | Станова | ПОКИ примірник має статус «на руках», система ПОВИННА блокувати його видачу і бронювання іншим `Reader`. | UC_Borrow |
| EARS-06 | Подієва | КОЛИ `Reader` повертає прострочену книгу, ТО система ПОВИННА створити `FINE`. | UC_Return |
| EARS-07 | Подієва | КОЛИ `Reader` або `Librarian` вводить валідні облікові дані, ТО система ПОВИННА перевірити запис у `USER` і надати доступ відповідно до ролі (UC_Auth). | UC_Auth |
| EARS-08 | Подієва | КОЛИ користувач вводить пошуковий запит, ТО система ПОВИННА повернути список `BOOK`, що відповідає запиту (UC_Search). | UC_Search |
| EARS-09 | Подієва | КОЛИ користувач застосовує фільтр за жанром або автором, ТО система ПОВИННА уточнити результати пошуку і повернути відфільтрований список `BOOK` (UC_Filter, extend від UC_Search). | UC_Filter, UC_Search |
| EARS-10 | Подієва | КОЛИ користувач ініціює оплату штрафу, ТО система ПОВИННА обробити платіж через зовнішній платіжний сервіс і, при успіху, встановити `FINE.paid` = true (UC_PayFine). | UC_PayFine |
| EARS-11 | Подієва | КОЛИ настає термін прострочення `LOAN`, ТО система ПОВИННА позначити `LOAN` як прострочений і МОЖЕ надіслати нагадування; `FINE` створюється лише при поверненні (EARS-06). Деталі таймера - припущення. | системний процес за розкладом (поза діаграмою `usecase.puml`) |

## Нефункціональні вимоги (NFR-01..NFR-04)

| ID | Вимога | Умови вимірювання |
| :--- | :--- | :--- |
| NFR-01 | система ПОВИННА опрацьовувати 95% запитів не довше 2 с при щонайменше 200 одночасних користувачів. | профіль - типові операції бібліотеки (пошук, видача, повернення); обсяг - 200 одночасних користувачів; метод - навантажувальний тест протягом 30 хв. Припущення: пороги не мають окремого ADR. |
| NFR-02 | інтерфейс ПОВИНЕН бути придатним для роботи на екранах desktop і мобільних пристроїв. | профіль - сучасні браузери; обсяг - основні екрани системи; метод - ручне/автоматизоване тестування інтерфейсу на різних розмірах екранів. Припущення. |
| NFR-03 | інтерфейс ПОВИНЕН бути україномовним. | профіль - усі екрани і повідомлення; метод - огляд інтерфейсу. Припущення. |
| NFR-04 | паролі ПОВИННІ зберігатися у вигляді хешу (bcrypt або argon2). | об'єкт - поле `USER.password_hash`; метод - аудит коду/тест. Припущення. |
