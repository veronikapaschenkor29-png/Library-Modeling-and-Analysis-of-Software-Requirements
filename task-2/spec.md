# Специфікація вимог: Бібліотека (Завдання 2)

## 1. Намір (Intent)
Формалізувати функціональні вимоги до бібліотеки, побудувати сценарії використання (Use Cases) і забезпечити трасованість вимог до сутностей даних із Завдання 1 (`BOOK`, `BOOK_COPY`, `MEMBER`, `LOAN`, `RESERVATION`, `FINE`, `USER`).

## 2. Сутності та ключові кроки
- **Сутності (ERD Завдання 1, `../spec.md`, розд. 2):** `BOOK`, `BOOK_COPY`, `MEMBER`, `LOAN`, `RESERVATION`, `FINE`, `USER`.
- **Видача:** читач запитує книгу → перевірка боргів (`EARS-02`) і ліміту 5 (`EARS-03`) → якщо примірник доступний, створюється `LOAN` на 14 днів, `BOOK_COPY.status` → «на руках»; якщо примірника немає → `RESERVATION` (`EARS-04`).
- **Блокування:** поки `BOOK_COPY.status` = «на руках», видача і бронювання іншим читачам блокуються (`EARS-05`).
- **Повернення:** оновлюється `LOAN` (`returned_at`, статус) і `BOOK_COPY.status` → «доступний»; при простроченні створюється `FINE` (`EARS-06`, ADR 0004).

## 3. Актори (Actors)
- **Людина:**
  - `Читач` - шукає книги, позичає, повертає, бронює.
  - `Бібліотекар` - видає і приймає книги (участь у `Return`).
- Зовнішні сервіси (email/SMS, платіжний шлюз) не є акторами; штраф створює система.

## 4. Критерії прийняття (Acceptance Criteria)
1. **Формат EARS:** усі вимоги `EARS-01..06` записані за синтаксисом EARS (`ears.md`).
2. **Зв'язок з ERD:** кожен Use Case прив'язано до сутностей ERD.
3. **Модель Use Cases:** `Borrow ..> CheckDebts : <<include>>`; `Reserve ..> Borrow : <<extend>>`; `CreateFine ..> Return : <<extend>>` (`usecase.puml`).
4. **Трасування:** матриця N:M між EARS та Use Cases; кожен Use Case має щонайменше одну вимогу (`trace-matrix.md`).
5. **Блокування/штраф:** `EARS-05` і `EARS-06` покриті Use Cases і Gherkin-сценаріями.
6. **Однозначність:** термін видачі - 14 днів; ліміт - 5 активних позик; прострочення → `FINE`; `BOOK_COPY.status` оновлюється при видачі/поверненні.
7. **NFR:** `NFR-01..NFR-04` (`../spec.md`, розд. 7) трасуються до UC і сутностей у `trace-matrix.md`.
8. **Рендеринг:** UML-версія - `usecase.puml` (PlantUML); Mermaid-блоки рендеряться на GitHub.
9. **Актори:** лише Читач і Бібліотекар (зовнішні сервіси не актори).

## 5. Use Cases
| Use Case | Актор | Опис | Зв'язки |
| :--- | :--- | :--- | :--- |
| `Borrow` (Позичити книгу) | Читач | Видача примірника на 14 днів | include `CheckDebts`; extend `Reserve` |
| `CheckDebts` (Перевірити борги читача) | система | Перевірка прострочених боргів і ліміту | include від `Borrow` |
| `Return` (Повернути книгу) | Читач, Бібліотекар | Повернення примірника | extend `CreateFine` |
| `CreateFine` (Створити штраф) | система | Створення `FINE` при простроченні | extend від `Return` |
| `Reserve` (Забронювати книгу) | Читач | Бронювання за відсутності примірника | extend від `Borrow` |

## 6. Вимоги EARS
- **EARS-01 (Event-driven):** WHEN читач запитує видачу AND примірник доступний, THE SYSTEM SHALL створити видачу з терміном 14 днів.
- **EARS-02 (Unwanted Behavior):** IF читач має прострочені борги, THEN THE SYSTEM SHALL відмовити у видачі з повідомленням.
- **EARS-03 (Unwanted Behavior):** IF читач уже має 5 позичених книг, THEN THE SYSTEM SHALL відмовити у видачі.
- **EARS-04 (Event-driven):** WHEN примірника немає в наявності, THE SYSTEM SHALL запропонувати бронювання і створити `RESERVATION`.
- **EARS-05 (State-driven):** WHILE примірник має статус «на руках», THE SYSTEM SHALL блокувати його видачу і бронювання іншим читачам.
- **EARS-06 (Event-driven):** WHEN читач повертає прострочену книгу, THE SYSTEM SHALL створити `FINE` (extend від «Повернути книгу»).

## 7. Нефункціональні вимоги (NFR)
- **NFR-01:** відповідь ≤ 2 с для 95% запитів при 200 одночасних.
- **NFR-02:** веб-інтерфейс desktop і мобільних.
- **NFR-03:** мова UI - українська.
- **NFR-04:** паролі хешуються bcrypt/argon2.

## 8. Gherkin-сценарії
`Feature: Позичення і повернення книги (EARS-01..06)` (`scenarios.feature`); сценарії:
- Успішна видача (EARS-01)
- Книги немає → пропозиція забронювати (EARS-04)
- Є прострочені борги → відмова (EARS-02)
- Перевищено ліміт 5 книг → відмова (EARS-03)
- Повернення простроченої книги → `FINE` (EARS-06)
- Примірник на руках блокується (EARS-05)

## 9. Трасування
Детальна матриця - `trace-matrix.md` (UC ↔ EARS ↔ Gherkin ↔ Sequence (task-3) ↔ Activity (task-4) ↔ Компоненти (task-5)). Коротка відповідність: `EARS-01` → `Borrow` → «Успішна видача»; `EARS-02` → `CheckDebts` → «Є прострочені борги → відмова»; `EARS-03` → `Borrow` → «Перевищено ліміт 5 книг → відмова»; `EARS-04` → `Reserve` → «Книги немає → пропозиція забронювати»; `EARS-05` → `Borrow`/`Reserve` → «Примірник на руках блокується»; `EARS-06` → `Return`/`CreateFine` → «Повернення простроченої книги → штраф».
