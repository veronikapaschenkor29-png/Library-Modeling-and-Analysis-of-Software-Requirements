# Специфікація взаємодії: позичення і повернення книги (Завдання 3)

## 1. Намір та критерії

Ця специфікація деталізує динаміку виконання Use Case `Borrow` (Позичити книгу), `Return` (Повернути книгу), `Reserve` (Забронювати книгу) та пов'язаних процесів із Завдання 2 (`CheckDebts`, `CreateFine`). Взаємодія моделюється за допомогою 5 окремих sequence-діаграм (D1–D5), кожна з яких покриває конкретний сценарій Gherkin з `task-2/scenarios.feature` / `task-2/README.md`. Модель узгоджена з EARS-вимогами Завдання 2, сутностями Завдання 1 (`BOOK`, `BOOK_COPY`, `MEMBER`, `LOAN`, `RESERVATION`, `FINE`) та ADR `0005`, `0006`, `0007` (`docs/adr/`).

Критерії (фіксуються комітом):
1. **Покриття сценаріїв:** створено 5 окремих sequence-діаграм (D1–D5) для сценаріїв EARS-01..06: D1 - успішна видача; D2 - примірника немає → бронювання; D3 - відмова через борги; D4 - перевищено ліміт 5 книг; D5 - повернення простроченої книги → `FINE`. Автоматична обробка прострочень фоновим `Overdue Scheduler` свідомо винесена за межі цієї роботи, оскільки вона ініціюється системним таймером, а не читачем/бібліотекарем.
2. **Учасники:** актор `Читач` (і `Бібліотекар` для повернення), клієнтський інтерфейс `Web UI`, сервіси (`Loan Service`, `Member Service`, `Catalog Service`, `Reservation Service`), сховище `БД` (сутності `BOOK`, `BOOK_COPY`, `MEMBER`, `LOAN`, `RESERVATION`, `FINE`) та інфраструктурні учасники (`Notification Service`, `Data Access`, `Payment Adapter`) - останні беруть участь опосередковано і не є окремими учасниками D1–D5.
3. **Строгий формалізм викликів та EARS-мітки:** усі повідомлення є сигнатурами методів із параметрами; опис дій прозою виключено. Кожен виклик між сервісами містить посилання на відповідну вимогу EARS (`EARS-01..06`); внутрішні виклики до `БД` реалізують ці вимоги на рівні збереження даних.
4. **Комбіновані фрагменти:** у кожній діаграмі присутній щонайменше один фрагмент `alt` (гілки боргів/наявності/ліміту/прострочення). Вибір гілок визначається результатом викликів до `Member Service`/`Catalog Service`/`БД`.
5. **Схема деактивації та обмеження Mermaid:** виклики створюють активацію (`->>+`). Повернення результатів і помилок у гілках `alt` виконуються пунктирними стрілками, а деактивація сервісів явно закривається через `deactivate` після відповідного фрагмента.
6. **Відповідність EARS:** еталонна версія взаємодії - Mermaid (`task-3/sequence.md`). При успішній видачі створюється `LOAN` з терміном 14 днів і `BOOK_COPY.status` → «на руках» (D1); при бронюванні створюється `RESERVATION` (D2); при поверненні простроченої видачі створюється `FINE` і `BOOK_COPY.status` → «доступний» (D5).

## 2. Учасники взаємодії

| Учасник | Тип | Роль та відповідність моделі |
| :--- | :--- | :--- |
| `Читач` | Актор | Користувач бібліотеки (`MEMBER`); ініціює видачу, бронювання, повернення |
| `Бібліотекар` | Актор | Приймає повернення книги (участь у `Return`) |
| `Web UI` | Компонент UI | Клієнтський веб-інтерфейс (поза ERD) |
| `Loan Service` | Сервіс | Координатор видачі/повернення: `borrowBook`, `returnBook`, створення `LOAN`/`FINE` |
| `Member Service` | Сервіс | Перевірка боргів і кількості активних позик (читає `MEMBER`/`LOAN`) |
| `Catalog Service` | Сервіс | Перевірка наявності примірника (читає `BOOK_COPY`) |
| `Reservation Service` | Сервіс | Створення `RESERVATION` при відсутності примірника |
| `Notification Service` | Сервіс | Надсилання повідомлень через outbox (опосередковано; не фігурує в D1–D5) |
| `Data Access` | Інфраструктура | Абстрагує доступ до БД (у sequence-діаграмах представлений як `БД`) |
| `БД` | Сховище | Реляційна БД (сутності `BOOK`, `BOOK_COPY`, `MEMBER`, `LOAN`, `RESERVATION`, `FINE`) |
| `Payment Adapter` | Адаптер | Оплата штрафів через зовнішній шлюз (опосередковано; не використовується в D1–D5) |

## 3. Основний потік та виконання сценаріїв

1. **Успішна видача (D1, EARS-01, EARS-05):** `Читач` → `Web UI.запит видачі` → `Loan Service.borrowBook(memberId, bookId)` → `Member Service.checkDebts(memberId)` → `БД.findOverdueLoans(memberId)`. У гілці `else` (боргів немає): `Catalog Service.getAvailableCopy(bookId)` → `БД.findAvailableCopy(bookId)` → `БД.createLoan(copyId, memberId, dueAt)` → `БД.updateCopyStatus(copyId, "на руках")`; повернення `loan створено`, `книгу видано (14 днів)`.
2. **Примірника немає → бронювання (D2, EARS-04, EARS-05):** `borrowBook` → `Catalog Service.getAvailableCopy(bookId)` → `БД.findAvailableCopy(bookId)` повертає `null`; у гілці `alt` `Loan Service` викликає `Reservation Service.createReservation(bookId, memberId)` → `БД.insertReservation(bookId, memberId)`; повернення `пропозиція бронювання`, `заброньовано`.
3. **Відмова через борги (D3, EARS-02):** `checkDebts` → `findOverdueLoans`; у гілці `alt` «Є прострочені борги» повертається `відмова (борги)` і `повідомлення про борги`; у `else` - продовження до перевірки ліміту/наявності (D1/D4).
4. **Перевищено ліміт 5 книг (D4, EARS-03):** `Loan Service` → `Member Service.countActiveLoans(memberId)` → `БД.countLoans(memberId)` (5); у гілці `alt` повертається `відмова (ліміт)` і `перевищено ліміт 5 книг`.
5. **Повернення простроченої книги → `FINE` (D5, EARS-06):** `Читач`/`Бібліотекар` → `Web UI.повернення книги` → `Loan Service.returnBook(loanId)` → `БД.findLoan(loanId)`; у гілці `alt` «Прострочено»: `БД.updateLoan(loanId, returned_at, status="повернено")`, `БД.createFine(loanId, amount, paid=false)`, `БД.updateCopyStatus(loan.copyId, "доступний")`; у `else` «Вчасно»: `updateLoan` і `updateCopyStatus` без `createFine`.

## 4. Обмеження та межі (Out of Scope)

- Автоматичне створення `FINE` за прострочення фоновим `Overdue Scheduler` (EARS-06 у фоновому режимі) виконується окремим демоном і не входить до даного Use Case, що ініціюється користувачем.
- Оплата штрафів через зовнішній платіжний шлюз (`Payment Adapter`) не моделюється в D1–D5 і може бути додана пізніше.
- `API Gateway`, `Auth Service`, `Identity Adapter`, перевірка сесії та `Notification Service` (повідомлення через outbox) не показані в sequence-діаграмах і залишаються поза межами цього Use Case.
- Електронні книги, міжбібліотечний обмін, фізична логістика (`../spec.md`, розд. 8).
